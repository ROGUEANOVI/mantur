# Testing

100% test coverage is the key to great vibe coding. Tests let you move fast, trust
your instincts, and ship with confidence — without them, vibe coding is just yolo
coding. With tests, it's a superpower.

## Stack

- **Unit / integration:** [Vitest](https://vitest.dev) + [Testing Library](https://testing-library.com/react)
- **End-to-end:** [Playwright](https://playwright.dev)

## Running tests

```bash
npm run test          # unit/integration tests (vitest), single run
npm run test:watch    # unit/integration tests, watch mode
npm run test:e2e      # end-to-end tests (playwright, spins up the dev server)
```

## Test layers

- **Unit tests** — pure functions with real logic (parsing, validation, formatting).
  Live next to the source file: `foo.ts` → `foo.test.ts`. No mocking of Supabase/Next —
  if a function needs those, it's not a unit test candidate as-is.
- **Integration tests** — component behavior with Testing Library (`@testing-library/react`),
  rendered in jsdom. Use `screen.getByRole`, not snapshot tests.
- **E2E tests** — real browser flows via Playwright, under `e2e/`. Cover the golden
  path for each user role (tourist, business owner, transporter, tourist guide, admin).

## Conventions

- File naming: `*.test.ts` / `*.test.tsx` next to the code under test (unit/integration),
  `e2e/*.spec.ts` for Playwright.
- Assertions must test real behavior — never `expect(x).toBeDefined()`. Assert the
  actual computed value, rendered text, or visible state.
- Regression tests generated by `/qa` carry an attribution comment pointing back to
  the issue and QA report that found the bug.
